🧪 Tech StackFrontend & MobileWeb Applications (Customer/POS/KDS/Admin): React.js / Next.js, TailwindCSS, Recharts, Lucide Icons.Waiter Mobile App: React Native / Expo (Optimized for one-handed operational efficiency).State Management & Realtime: Redux Toolkit / React Query, Socket.IO Client.Backend & Micro-servicesCore API: Node.js, Express.js (or NestJS), TypeScript.Realtime Engine: Socket.IO Server.Authentication: JSON Web Tokens (JWT) with short-lived Access Tokens & Refresh Tokens in HttpOnly Cookies, Bcrypt password hashing.AI Engine & Data ProcessingRecommendation System: Python / FastApi (Collaborative Filtering / Association Rule Mining).Revenue Forecasting: Time-series Forecasting (Prophet / ARIMA / Holt-Winters).Database & StorageRelational Database: PostgreSQL (or MongoDB with Mongoose).Cache & Session Management: Redis (Socket.IO adapter, session caching, rate limiting).Cloud File Storage: Cloudinary (Menu item images, receipts).👥 User Roles & Permissions (RBAC)ROMS implements strict Role-Based Access Control (RBAC):RoleAccess Level & Key ResponsibilitiesCustomerAccess online menu, place QR orders at table, track food progress, book tables, join loyalty program.WaiterMobile table layout viewing, assistance ordering, table check-in, merge/split tables, request pre-print bill.ChefReceive FIFO kitchen queue, update cooking states (Cooking/Ready), trigger out-of-stock alerts, prioritize dishes.CashierManage POS checkout queue, scan loyalty cards/coupons, process multi-mode billing, execute bill splitting.ManagerMenu & pricing management, inventory PO approval, shift scheduling, AI forecast analysis, promo setup.AdminFull system configuration, RBAC privilege mapping, user account lifecycle, read-only Audit Log viewing.📋 Functional Modules & Core User Stories1. Customer Module (9 Stories Total)Member Registration & Login: Phone number validation and JWT authentication.Online Reservation & Deposit: Select date/time/headcount, pre-order dishes, auto-trigger 40% deposit for orders $> 1,000,000\text{ VND}$.QR Dine-in Ordering: Instant table identification from QR parameter, submission creates real-time order.AI Recommendation Engine: Cross-selling popup recommendations when dishes are added to cart (e.g., Hotpot $\rightarrow$ American Beef / Craft Beer).Real-time Order Progress Tracking: Progress bar updating instantly (Created $\rightarrow$ Cooking $\rightarrow$ Ready $\rightarrow$ Served) without page reload.2. Waiter Module (10 Stories Total)Real-time Table Map: Interactive floor plan showing status changes ($< 2\text{s}$ latency when customer scans QR).Reservation Check-in: Search reservation ID or scan customer phone QR to convert reservation to Occupied.Proxy Ordering: Place orders on behalf of tech-averse customers with custom item notes (e.g., "No onions", "Less spicy").Table Merge / Split: Combine tables ($B01 + B02$) merging cart/bill into a unified order ID.Pre-print Bill Request: Send draft bill print requests to cashier printer for customer verification.3. Kitchen Module (7 Stories Total)Real-Time FIFO Kitchen Queue: Incoming orders stream automatically with distinct audio cues and item groupings.Dish Processing State Updates: Transition items from Pending $\rightarrow$ Cooking $\rightarrow$ Ready, triggering instant push notifications to Waiters.Out-of-Stock Alert: Toggle item as "Out of stock" directly from KDS, instantly disabling the item on Customer QR & Waiter apps.Order Item Rejection: Reject item with reason entry (e.g., "Kitchen closed"), notifying Waiter and auto-deducting cost.Priority Queue Management: Executive chef override to push VIP or delayed orders to the top of the queue (High Priority).4. Cashier Module (7 Stories Total)Checkout Queue Monitor: Visual checkout queue with flashing alerts for payment-requested tables.Loyalty & Discount Integration: Auto-apply membership tiers (e.g., Gold = 10% off) and coupon validation.Multi-Payment & Final Billing: Cash, QR Transfer, E-wallet processing $\rightarrow$ mark order as Paid, set table to Cleaning, award loyalty points.Split Bill: Split balance equally or by distinct item groups across multiple payments.Refund / Void Transaction: Manager passcode required to void or refund transactions with automated Audit Logging.5. Manager Module (12 Stories Total)Menu & Price Control: Add/edit dishes, upload media to Cloudinary, modify prices in real time.Inventory Control & Stock-In: Manage raw ingredients, approve stock-in slips, set low-stock warning limits.Employee Scheduling: Weekly shift scheduling with anti-collision checks and push alerts.AI Analytics Dashboard: Executive Recharts dashboard detailing historic metrics and time-series AI forecasts.Promotions & Special Events: Setup date-bounded promotions, coupon codes, and birthday rewards.6. Admin Module (6 Stories Total)User & RBAC Management: Account provisioning, role assignments, middleware-level access locks.Immutable Audit Logging: Read-only tracking of sensitive actions (price overrides, voids, refunds) recording Timestamp, User ID, Action, IP, and Diff Payload.⚖️ Business RulesReservation Anti-Collision Rule: Physical tables cannot have overlapping reservations within a 90-minute window.Order Lifecycle Rule: An order item cannot enter Cooking state until the order status is verified as Confirmed (via QR submission or Waiter confirmation).Payment Completion Rule: Cashiers cannot finalize an order to Paid status unless all associated items are either marked as Served or officially rejected/canceled.Financial Modification Rule: Financial changes (menu price changes, payment voids, refunds) strictly require Manager role authentication.Inventory Safety Rule: When stock drops below configured minimum limits, mandatory alerts are dispatched to the Manager dashboard, and auto-ordering for reliant recipes is restricted upon Chef stock-out confirmation.🗄 Database Schema & Data FlowPrimary Entities & RelationshipsUsers & Roles: User (1) ---- (N) Order, User (1) ---- (1) RoleTable & Area: Area (1) ---- (N) Table, Table (1) ---- (N) OrderOrder & Order Items: Order (1) ---- (N) OrderItem, OrderItem (N) ---- (1) MenuItemMenu & Recipe Inventory: MenuItem (1) ---- (N) Recipe, Recipe (N) ---- (1) InventoryItemLoyalty: User (1) ---- (1) LoyaltyAccount, LoyaltyAccount (1) ---- (N) PointTransaction💻 Installation & SetupPrerequisitesNode.js: v18.x or highernpm / yarn / pnpmPostgreSQL: v14+ or MongoDB v6+Redis: v6+Python: v3.9+ (for AI module)1. 🔌 API Documentation SummaryBase URL: /api/v1Authentication & RBACPOST /auth/register - Customer account creation.POST /auth/login - User login (returns Access Token & sets Refresh Cookie).POST /auth/refresh-token - Refresh expired Access Token.Table & ReservationsGET /tables - Get real-time status of all tables.POST /reservations - Create reservation with pre-orders.POST /reservations/:id/check-in - Waiter check-in for reserved table.Menu & QR OrderingGET /menu - Fetch menu items (supports category filters).POST /orders - Place new order (Customer QR or Waiter proxy).POST /orders/recommendations - Get AI recommended items based on current cart payload.Kitchen DisplayGET /kitchen/queue - Get active FIFO order item queue.PATCH /kitchen/items/:id/status - Update dish processing status (Pending $\rightarrow$ Cooking $\rightarrow$ Ready).POST /kitchen/items/:id/out-of-stock - Mark item as depleted.POS & BillingGET /checkout/queue - Cashier list of unpaid tables.POST /checkout/split - Divide invoice by items or headcount.POST /checkout/pay - Complete payment, update order to Paid, release table to Cleaning.🔒 Non-Functional Requirements & SecurityHTTPS Enforcement: All HTTP communications encrypted via SSL/TLS in production.Password Hashing: Passwords hashed using bcrypt with salt round factor $\ge 10$.Token Security: Short-lived JWT Access Tokens ($15\text{ mins}$) + HttpOnly, SameSite Refresh Tokens.Realtime Performance: Socket.IO synchronization latency across Client, Waiter, and KDS $< 2\text{ seconds}$.Responsiveness: Fully responsive UI/UX across Desktop, Tablet, and Mobile.
